# 社媒传播与多页计划

在创作/改编前阅读；构图、素材、HTML 和整组审核都使用同一个 `series-plan.json`。爆款是传播目标，不是结果承诺。这里的 CTA 指 call to action（行动引导）；用户写 CAT 时按上下文理解为 CTA，含义确有不同再澄清。

## 把传播目标写成可执行决策

| 项 | 决定什么 | 在哪里消费 |
|---|---|---|
| audience + promise | 给谁看，能获得什么具体价值 | 选题、封面、内容取舍 |
| hook.text + mechanism | 用户为何停下来：识别需求、可见反差、明确收益或未解问题 | 封面文案、主视觉和缩略图检查 |
| pages[].message | 这一页新增了什么，支持哪个承诺 | 逐页写作与信息层级 |
| pages[].swipeReason | 下一页具体会补充什么，为什么值得继续 | 页序、承接句、跨页构图 |
| payoff | 哪一处交付答案、方法、证据或情绪落点 | 内容完成度和结尾检查 |
| cta | 是否需要行动，做什么，以及对受众有什么用 | 结尾或适当节点的行动引导 |
| visualDirection | 全组共享字体、色彩、素材风格及节奏 | 一张参考联系表、所有素材与 HTML |

钩子表达内容真实提供的价值。正文尽早给第一份收益，再递进到更具体的方法、比较、细节或结果。翻页理由可以由内容和图像关系承担，不必每页写“往后看”。结尾兑现开头承诺；CTA 根据目标选择收藏、讨论、分享、关注或商品动作。没有适当动作时 `enabled=false`，不强加互动请求。

## 按内容组织，避免套路化

- 教程：问题识别 → 关键步骤 → 易错点/完整办法；每一步有可操作信息。
- 清单/比较：先给选择标准，再给差异与结论；不用几个同义标题凑页。
- 故事/摄影：场景、变化、细节与情绪承接；不把摄影组图硬改成知识卡。
- 观点：主张、依据、解释或反例；不通过虚构争议制造反差。
- 商品：使用情境、真实对象、具体价值与适用边界；数据只来自资料。

这些是组织参考，用户主题、原帖逻辑和指定场景优先。忠实复刻先保留参考的钩子和页序，用户要求改编时再重写；审核原帖有缺点不代表获准擅自改稿。

## 计划怎么写、怎么消费

复制 `<skill>/assets/series-plan.example.json` 的字段形状，针对当前主题写具体内容，不把示例主题带入作品。先创建对应页，执行 `plan --dir P --file F`；命令校验页序、必填信息、翻页理由及 CTA。单图无需翻页理由，但仍应有明确主张和兑现。字段完整不代表策略有效，实际效果由看图和读内容判断。

`series prompt` 将每页 copy、message、visual、swipeReason 和全组方向写进同一提示词，明确一张图片包含全部页面、count=1，并按页面比例和页数选栅格（三页 9:16 排成一行三格，四页 9:16 排 2×2），把栅格和每格的页面比例写进提示词，同时记入工程 `concept.grid` / `concept.aspect`，`image prepare` 据此定画幅。制作素材时让主视觉支持对应 message，排版时让 hook 和关键信息有可见层级。审核每页可读性后，用 `review --page series` 记录：封面承诺是否真实、正文是否递进、下一页是否有新增价值、结尾是否兑现、CTA 是否匹配目标和平台。

全组共享字体角色、色彩用途、边距、编号与主体风格；各页改变主次、图片尺度和信息结构。单页的漂亮不能抵消漏页、重复、断层或结尾没兑现。以手机阅读宽度检查正文，以整组缩略图检查重复和节奏。
