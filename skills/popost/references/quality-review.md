# 质量检查与真实记录

三个问题分开判断：工程能运行吗；画面与内容好不好；编辑保存后是否仍然正确。任何记录都必须来自本次实际检查，不伪造用户认可或模型实测。

## 逐页

render 后先用 `sheet --dir P --compare` 一张图看全篇（复刻时参考在上、成品在下），再只打开需要核对细节的那几页 PNG：小字、商品还原。每张打开的图都留在对话里，拖慢之后的每一步。逐字读文字，检查漏字错字、乱码、遮挡、溢出、换行、对比、对齐、裁切、主体尺度、图片拉伸变形（与原图宽高比不符）、同一张图冒充不同款式、素材错配与占位内容。按参考检查关键版式和细节；字体近似等差异说明。先把每页要改的地方收齐，一页只重写或编辑一次；改完用一次 `render --page all` 重渲所有改过的页，再用一次 `sheet` 重新看图，不改一处渲染一次，也不把“文件已生成”当成已完成。

在 design.md 记实际发现、改动和重渲结果，确认当前图后执行 review --page ID --note 具体观察。命令校验 HTML/尺寸/本地资源指纹和 PNG 哈希，拒绝用旧图审核新 HTML。记录标 reviewer=agent，用户明确同意才另记用户认可。

## 整组传播与设计

用 series-plan.json 对照：封面 hook 是否可见且可信；正文是否有新增信息；各页是否建立继续阅读的理由；开头承诺是否兑现；CTA 是否为受众提供合理下一步。用 `sheet --dir P` 看整组缩略图查重复与节奏，看单页手机尺度查可读性。忠实复刻先按用户要求还原，不借优化之名改变用户锁定的内容。

检查共享字体、色彩、主体、编号与页序；场景 profile 的设计规则逐项核对。完成后 review --page series --note 实际判断。传播策略字段完整只证明计划可消费，不证明一定爆款。

## 工程与编辑

build 输出 structureReady、reviewGaps、readyToDeliver。每页已渲染且当前版本逐页/整组记录完整，才可最终交付；预览 render/export 可随时用，最终图片 export --final 检查完成状态。

每篇确认图片已加载、字体确实命中、画布尺寸与 PNG 一致，并在宿主侧栏检查当前作品和编辑入口。新增编辑器版本、宿主适配或特殊页面结构时，完整测试改文字/图片、保存、刷新、下载与 ZIP 换目录恢复；普通作品沿用已验证的这些机制，遇到异常再复测对应操作。不要为测试而反复修改真实发布文件。导出应保持当前已审核 PNG 的原始字节；缓存失效或主动重渲后，重新看变化页并记录。可自动检查几何/像素一致性，视觉内容仍需实际看图。若同一问题反复修不好，重新判断布局或素材架构，不通过重复生图堆成本；内部概念始终只有一次生成。
